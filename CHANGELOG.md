# changelog

## 3.0.22
* idle and reinvest treat an unreconciled batch as not yet paid only when its unbonding end came from the chain (`CHAIN_REPORTED_END`) and is still ahead; a batch whose end is only the configured estimate counts as owed until reconciled, so its early-arriving funds are never swept; bond pricing counts recorded rewards up to the balance whatever batches are owed; `ReinvestIfNeeded` also skips (keeping rewards recorded) when no active validator is bonded
* bonds now reject a deposit that would round down to zero derivative tokens instead of delegating the user's funds for no shares; `Reinvest` no longer emits a zero-amount delegation when the configured fee is 100%, and sends the full reward to the fee account without requiring an active delegation target
* the first bond at zero supply mints the bonder 1:1 and locks dead shares in the hub (`DEAD_SHARES`, event attribute `dead_shares`) worth whatever backing is already there (stake, rewards, idle), at least 1000 (the unbacked part of that minimum comes out of the bonder's mint, so the rate stays 1:1 and a deposit too small to cover it is refused), so the bonder cannot claim the leftover and donating to an empty hub to inflate the price costs the donor almost all of it; idle counts only batches whose funds can already be in the balance (reconciled or matured), so `ReinvestIdle` works on a hub with batches in flight; while the reserve initialisation is pending, bond pricing still counts recorded rewards; `Harvest` ends with `ReinvestIfNeeded`, so it skips instead of reverting when nothing can be bonded; an unparsable `coin_received` event is skipped (`unparsed_coin_received`) instead of failing the staking reply
* rewards withdrawn automatically by bond / unbond / redelegate / rebalance / remove-validator are now recorded (hub-tf replies to every staking message, like the CW20 hub) and reinvested at the next harvest; `Reinvest` bonds the recorded rewards instead of a balance delta that skipped them, and never bonds funds owed to matured batches
* new `QueryMsg::IdleFunds` and owner-only `ExecuteMsg::ReinvestIdle { amount }` to find and restake native that sits in the contract unaccounted for (legacy unrecorded rewards, late unbonding funds), fee-free, to active validators the chain has bonded; a sweep mints proportional dead shares to the hub so moving unpriced idle into delegated backing cannot raise the exchange rate for a front-running bonder; what batches are owed comes from the running `NATIVE_RESERVED` total plus the few unreconciled batches, and nothing counts as idle while the reserve initialisation is pending
* new bonds are priced including the holders' share of rewards not yet restaked (recorded and still accruing), so a bonder no longer buys into rewards earned before they arrived; untracked (idle) native is not counted, since anyone could raise it with a plain transfer to inflate the price; `ReinvestIfNeeded` applies the same cap as `Reinvest` and skips instead of reverting `RedelegateInactive` when recorded rewards cannot be bonded yet
* clearer events for the reconcile flow: `steakhub/reconcile_observed` lists `deferred_ids` (matured batches held back by a newly observed one) and `retry_after_height`; `steakhub/withdraw_awaiting_reconcile` carries `amount_refunded=0` and `retry_after_height`; `steakhub/unbonded_withdrawn` lists still-open `dust_ids`; `Reconcile` always reports `native_reserved` (`pending` during initialisation); the reserve initialisation reports the recorded rewards it held out of the pool (`unlocked`); `migrate` says what to do while the reserve is pending (`next_step`)
* a batch that matures while the reserve initialisation is summing joins its pool (without restarting the sum), so that batch's loss is shared with the pool instead of being charged to the older batches as if it had been paid in full; `WithdrawUnbonded` succeeds without paying only for a batch first observed in the current block (bundled after `Reconcile`), and otherwise asks for `Reconcile`; a claim that currently rounds to zero gets an explicit error
* `WithdrawUnbonded`: a withdrawal that finds only matured batches still awaiting `Reconcile` records them and succeeds (`steakhub/withdraw_awaiting_reconcile`), so a client bundling `Reconcile` + `WithdrawUnbonded` is not stuck; a claim whose share rounds to nothing is kept while its batch still holds value; requests in fully written-down batches are cleared and listed in `zero_refund_ids`; reserve releases use checked accounting and fail before changing claim state if the reserve invariant is broken, preventing a reconciled claim from consuming funds belonging to another accounting bucket
* `Reconcile` keeps a running total of what reconciled batches are owed (`NATIVE_RESERVED`) instead of scanning every reconciled batch, which grew without bound as unbond requests went unclaimed. The one-time initialisation after migration pools the reconciled batches older versions left (possibly over-stated) with the matured unreconciled batches, shares any shortfall among them pro rata, and works through up to 100 batches per `migrate` / `Reconcile` call (a short history finishes during `migrate`) (event `steakhub/reserve_initialization`); withdrawals wait until it completes
* `Reconcile` records the first block in which a batch is observed past its estimated unbond end and waits for a later block before accounting it, so the staking module always gets an EndBlock opportunity to pay matured unbondings; every matured batch must pass that gate before any are reconciled, preventing one batch's funds from masking another's loss; reconciled obligations are reserved, write-downs are shared pro rata to what each batch holds (cumulative rounding, each within one unit of its exact share) and conserve the exact capped shortfall, and fully written-down requests remain cleanly claimable
* `SubmitBatch` takes each batch's unbonding end from the staking module's `unbond` event (`completion_time`, the latest across its undelegations) instead of `submit time + unbond_period`, so a configured `unbond_period` that differs from the chain's can no longer make `Reconcile` write a batch down before its funds are paid; a difference is reported as `steakhub/unbond_completion_time`, and the estimate stays if the chain reports no completion time
* the reward reinvest that follows `RedelegateInactive` honours its `exclude` list, so an excluded validator that refuses new stake can no longer revert every re-run (`CallbackMsg::HarvestAfterRedelegation` / `ReinvestIfNeeded` gain a defaulted `exclude` field)
* add owner-only `RedelegateInactive { limit, exclude }` to both hubs: moves stake off validators outside the active set (paused, or removed without redelegation) onto the active validators the chain currently has bonded. Each redelegation is an isolated submessage, so ones the staking module refuses (transitive redelegation, max entries) are skipped and reported, and the call can be re-run once they mature; `exclude` keeps known-blocked validators from using up `limit` (default 25, max 50). Rewards withdrawn by the redelegations are harvested and reinvested atomically through the new `CallbackMsg::HarvestAfterRedelegation` / `ReinvestIfNeeded`; a reward-finalization failure reverts the transaction so no reward balance can be stranded, and reinvestment targets only active validators currently bonded on chain
* `pfc-steak` 3.0.21: new `ExecuteMsg::RedelegateInactive` and `CallbackMsg` variants

## 3.0.21
* account for every on-chain delegation exactly once when reporting state and submitting batches
* repair and preserve the active-validator registry invariant during migration and validator updates; migration drops active entries for removed validators instead of re-whitelisting them
* a failed automatic batch submission no longer reverts the user's unbond request
* reject empty or unbacked staking operations and use checked exchange-rate arithmetic
